Introduction/Purpose:

The inventory system is designed to be customizable to fit every game you make. It has an inventory grid that developers can change to have big or small inventory space and has the compatibility for multi-grid items. The system also has adding/removing items to the inventory built in so developers can implement item pickup/drop features. The inventory also has a customizable context actions for items so you can add functions like equipping, dropping, using, and etc. The system also features a customizable hotbar, you can also have it extend the inventory or turn off the hotbar completely if its not needed. Some user-generated mod support is allowed for custom items and custom context actions allowing developers for mods to be creative.



Functional Requirements:

1: Shall have the ability to change the size of the inventory

2: Shall have the ability to add/remove items

3: Shall have the ability to detect and mitigate duping items

4: Shall have the ability to change the behavior of moving items(allow to move items)

5: Shall have the ability to trigger an event if an item is dragged on-top of another item

6: Shall have the ability to show item description and attributes when hovering over an item

7: Shall have the ability to have multi-grid items(items that take up more than a 1x1 space)

8: Shall have the ability to add visual and sound effects to the UI

9: Shall have the ability to add extra functional UI(for example, buttons)

10: Shall have the ability to disable/enable opening the inventory(for example, during an important game cutscene)

11: Shall have the ability to customize the hotbar(fast action, extend inventory, or disabled)

12: Shall have the ability to customize the UI of the inventory system



Non-Functional Requirements:

1: Shall not have vulnerabilities that can lead to attacks

2: Shall load the inventory under 1-2 seconds

3: Shall not cause performance issues that lead to unsteady frame times

4: Shall have support for custom items and context actions

5: Shall not have redundant code that reduces performance



Use-Case Descriptions:

1: Single-player survival game

2: Single-player horror game

3: Multiplayer fps game
